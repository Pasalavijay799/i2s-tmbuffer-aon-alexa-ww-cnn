1. Introduction
EdgeSphere Tool for GPX AI Processor
The EdgeSphere Tool is a utility tool built for the GPX AI Processor, focusing on streamlining audio
and video data collection, firmware deployment, and model compatibility at the edge. In this
version, EdgeSphere offers a clean and efficient interface that allows users to capture audio and
video samples, making it ideal for building datasets tailored to edge AI applications.
1.1.
Launching EdgeSphere

You can launch it by navigating to the directory where you installed the tool.
(For example, in this case, C:\EdgeSphere [See Fig 1])

After successful installation, you’ll find the EdgeSphere application along with some
necessary files in the installation folder.

To launch the tool, simply double-click or right-click and select “Open” on the
EdgeSphere application.

2.3.1.
Audio Data Collection

--- PAGE 11 ---
11
Fig 8
On the left side, you'll find a minimal UI designed to guide the user through the
recording process. It provides visual cues to help users know when to speak and
ensures accurate timing during audio capture. [See fig 8]
On the right side, there are several input fields that the user needs to fill out before
starting the recording. Each field is accompanied by a helpful tool tip that explains
what information is required.[See fig 8]
The tool collects audio data using the on-board I2S microphone with a sampling rate
of 8 kHz, ensuring efficient and lightweight data capture suitable for edge AI
applications.
For e.g., Person Name: Ambient, Word to record: Hello, Duration of sample in
seconds: 1, Number of samples: 10
Once the data collection has been completed, you can see the result in the result log,
or you can navigate to the directory “C:\EdgeSphere\Collected_Data\Audio” to see
the collected audio samples in .wav format.
2.3.2.
Image Data Collection

--- PAGE 12 ---
12
Fig 9

On the left side, you'll see a minimal UI featuring a live streaming window and a Capture
button. This allows users to preview the video feed in real time and capture images when
ready. [See fig 9]

On the right side, users are required to fill in several input fields, each accompanied by a
tool tip providing guidance on what information to enter. [See fig 9]

The tool supports image capture from the on-board HM01B0 camera, which is an I2C-
based camera module. Additionally, users can choose to capture images using a laptop
webcam or any external USB webcam connected to the system.

When capturing the image, the image save directory will be displayed below the capture
button.

2.4.
Result Log
Fig 10

Initially, the window will display “No files found”. Once you collect audio samples, the data
will appear here in the form of an Excel sheet with a timeline view representing each
recorded entry. [See fig 10]

You can play back the recorded samples, transcribe audio data, download the files, and
delete them once they are no longer needed — all directly from this interface.

In the top-left corner, there is a slider labeled with three transcription model options:
o
Small – Fastest processing, but with lower accuracy.
o
Medium – Balanced in speed and accuracy.
o
Large – Slower but provides the most accurate transcription results.

Based on your requirements (speed vs. accuracy), you can slide between these models to
transcribe the recorded data accordingly.
